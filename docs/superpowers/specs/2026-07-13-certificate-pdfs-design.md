# Design: Certificate PDF infrastructure for award cards

**Date:** 2026-07-13
**Status:** Approved (pending spec review)

## Goal

Let Harun attach the actual certificate PDFs to the honors shown on the Awards page,
by simply dropping a PDF into a folder. Cover the four certificates he mentioned:
IEEE Senior Member, SCRS Fellow, Hackathon Raptors Fellow, and IJTAIA Peer Reviewer.

Three of these already exist as `Honor` entries in `lib/awards.ts`
(`ieee_member`, `scrs_fellow`, `raptors_fellow`); IJTAIA is new.

## Decisions (from brainstorming)

1. **Placement:** Attach certificates to the *existing* award cards on the Awards
   page — not a separate section or page. IJTAIA is added as a new card.
2. **Mechanism:** *Auto-detection.* Dropping `public/certificates/<key>.pdf` is
   enough; a prebuild script scans the folder and the matching card's button
   appears automatically. Removing the PDF removes the button. (The site is a
   static export — `output: 'export'` — so file existence cannot be checked at
   runtime; detection happens at build time.)
3. **IJTAIA section:** Goes into the existing **Jury** section, broadened
   conceptually to "Jury & Review Roles" rather than opening a one-item section.
4. **IEEE grade:** The `ieee_member` entry is upgraded from "Professional Member"
   to **Senior Member**. The label stays English **"Senior Member"** in both
   locales (IEEE grades are conventionally referred to in English).

### Alternatives considered

- *Separate Certificates page/section* — rejected: 3 of 4 items already live on the
  Awards page; a second surface would duplicate and fragment them.
- *Explicit `certificate: true` flag per honor* — rejected in favor of auto-detection
  per the user's "just drop the PDF" requirement.

## Architecture

### File naming convention

- New folder: `public/certificates/`
- PDFs are named by the honor `key`, served at a locale-independent static path:

  | Certificate | `key` | File | Served at |
  |---|---|---|---|
  | IEEE Senior Member | `ieee_member` | `ieee_member.pdf` | `/certificates/ieee_member.pdf` |
  | SCRS Fellow | `scrs_fellow` | `scrs_fellow.pdf` | `/certificates/scrs_fellow.pdf` |
  | Hackathon Raptors Fellow | `raptors_fellow` | `raptors_fellow.pdf` | `/certificates/raptors_fellow.pdf` |
  | IJTAIA Peer Reviewer | `ijtaia_reviewer` | `ijtaia_reviewer.pdf` | `/certificates/ijtaia_reviewer.pdf` |

- A `public/certificates/README.md` documents the convention and the valid keys,
  and keeps the folder tracked in git while empty.

### Build-time detection

- **`scripts/gen-certificates.mjs`** (Node, ESM): reads `public/certificates/`,
  collects the basenames of `*.pdf` files (minus extension), and writes
  **`lib/certificates.ts`**:

  ```ts
  // AUTO-GENERATED by scripts/gen-certificates.mjs — do not edit by hand.
  export const certificateKeys: string[] = ["ieee_member", "scrs_fellow"];
  ```

- **`package.json`** gains `predev` and `prebuild` lifecycle scripts, both running
  `node scripts/gen-certificates.mjs`, so the manifest is regenerated before every
  `next dev` and `next build`.
- `lib/certificates.ts` is committed to git (the script keeps it fresh). This keeps
  imports/type-checking/lint resolvable on a clean checkout and makes PDF additions
  show up as a reviewable diff. It is regenerated, not hand-edited.
- No filesystem access happens at runtime, so this is fully compatible with the
  static export.

### Awards card change (`app/[locale]/awards/page.tsx`)

- `HonorCard` imports `certificateKeys` from `@/lib/certificates`.
- When `certificateKeys.includes(honor.key)`, the card renders a small button/link:
  - lucide `FileText` icon + text `t("awardsPage.viewCertificate")`
  - `href={`/certificates/${honor.key}.pdf`}`, `target="_blank"`,
    `rel="noopener noreferrer"`
  - styled consistently with existing card links (muted → primary on hover)
- When the key is absent, nothing is rendered (no broken links).

### Data & content changes (`lib/awards.ts`)

- New honor appended:

  ```ts
  {
    key: "ijtaia_reviewer",
    section: "jury",
    organization: "IJTAIA",
    organizationUrl: /* TBD — provided by user */ undefined,
    date: "2026",       // TBD — confirm appointment date
    current: true,      // TBD — confirm if ongoing
  }
  ```

- No type change to `Honor` (reuses `section: "jury"`).

### Translation changes (`messages/tr.json`, `messages/en.json`)

- `awardsPage.viewCertificate` → TR "Sertifikayı Gör", EN "View Certificate".
- `awardsPage.sections.jury` → TR "Jüri & Hakemlik", EN "Jury & Review Roles".
- `awards.honors.ieee_member` → title "Senior Member" (both locales); description
  updated to reflect the Senior Member grade.
- `awards.honors.ijtaia_reviewer` → new title/description (draft copy, to be
  confirmed by the user).

## Content still needed from the user (does not block the infrastructure)

- IJTAIA: exact journal name, official URL, appointment date, whether ongoing.
- The four certificate PDFs themselves.

Until the PDFs are dropped in, the cards render exactly as today (no buttons); the
IJTAIA card appears once its entry + copy are confirmed.

## Verification

- `npm run build` and `npm run lint` both pass.
- Drop a throwaway `ieee_member.pdf`, run the generator, confirm the button appears
  only on the IEEE card and opens the PDF; remove it and confirm the button
  disappears. (Manual visual check via `npm run dev`.)

## Out of scope

- Inline/modal PDF viewers or thumbnail previews (button opens the PDF in a new tab).
- Any change to the Media page or other sections.
- Bulk dependency/security updates flagged by Dependabot (tracked separately).
